# book-finder-starter

自分の好きな本で、「本をえらぶ → 近くの図書館で 借りられるか 確かめる」ページを作るための **骨組み（スターターキット）** です。

本棚は **0冊** から始まります。本は、あなたが自分で入れます。

## ⚠️ はじめに（大事なこと）

- これは、個人が作った **非公式** の見本です。どの会社・団体・サービスとも関係ありません
- **保証はありません**。使うときは、ご自身の判断と責任でお願いします
- 図書館の検索サービス（カーリル）を使うときは、**あなた自身の鍵（APIキー）** と契約で使います。作者の鍵は入っていません
- 外のサービスの使い方は、それぞれの **最新の利用規約** を、使う前に必ず確かめてください

## できること

- 本棚：`data/books.csv` に書いた本を、ページで表示する
- えらぶ：かんたんな質問（気持ち・長さ など）に答えると、タグの合う本が出る
- 図書館：地域をえらぶと、その本が近くの図書館にあるか確かめる（**自分の鍵を入れたときだけ**）
- 守り：鍵をかくす中継・回数を数える係・急ぎの停止スイッチ・見張りのテスト

## まず、手元で動かす

必要なもの：Node.js 22 以上

```
npm test               # テスト（外のサービスには つながりません）
npm run dev            # http://localhost:8788 （あなたの本棚・見本モード）
npm run dev -- --demo  # 見本の本3冊で、ためしに動かす
```

手元のページは、**いつも見本モード** です。鍵は使わず、外には何も送りません。

## 本を入れる

1. `data/books.csv` に、1行に1冊ずつ書きます

   ```
   isbn,title,author,tags
   9784xxxxxxxxx,本の名前,書いた人,easy|short
   ```

   - `isbn`：本の番号（ISBN・**13けた**。978 か 979 で始まる）。ハイフンは あってもなくても大丈夫。番号の形と、チェック用の数字を点検します
   - `tags`：半角の英小文字・数字（`easy` `cheer` など）。いくつかは **`|`（縦の線）** で区切ります
2. `npm run build:books` で、`public/data/books.json` を作ります（ネットにはつながりません）
3. 質問と答えは `public/js/tags.js` で変えられます。どの本も持っていないタグの答えは、自動で かくれます

## 本物の図書館に つなぐ（使う人だけ）

ここから先は、**自分のホスティング（例：Cloudflare Pages と Workers）** と **自分のカーリルの鍵** が必要です。

1. カーリルの API キーを、自分で取ります。利用規約（表示の決まり・回数の決まりを含む）を確かめます
2. `workers/counter/` の「回数を数える係」（Durable Object）を、先に公開します
3. ページ（`public/` と `functions/`）を公開し、設定に次を入れます
   - `CALIL_APPKEY`：あなたの鍵（**秘密の設定** に入れる。コードや画面には書かない）
   - `CALIL_COUNTER`：2 の Counter クラスへの つなぎ（Durable Object のバインディング）
4. 中継は、設定によって こう動きます

   | 状態 | 動き |
   |---|---|
   | 鍵がない（はじめ）| **見本モード**。カーリルには つながない |
   | 鍵はあるが、数える係がない | **閉じる**。問い合わせを止める |
   | 鍵と 数える係がある | カーリルへ。毎回、先に数える係に聞く |

5. 急いで止めたいとき：設定で `CALIL_ENABLED=false` にして、公開し直します

## 通信する先と、送る情報

| どこから → どこへ | 送るもの |
|---|---|
| ページ → あなたのサイトの `/api/calil/*` だけ | 都道府県・市区町村、本の番号（ISBN）、図書館の番号 |
| 中継 → カーリル（`api.calil.jp`）| 上と同じもの ＋ あなたの鍵 |

- ページは、自分のサイトの外へは 直接 通信しません（CSP という決まりで止めています）
- 名前・メールアドレス・アカウントは 集めません

## 保存する情報

- ブラウザ：保存しません
- 数える係：1時間ごとの 問い合わせの回数と、図書館ごとの 1分間の回数
- 中継の入口：接続元（IPアドレス）ごとの 1分間の回数を、メモリに（古い回数は、次に問い合わせが来たときなどに 片づけます。ずっと残すことはしません）

## 回数の数え方（図書館に 負担をかけないため）

- サイト全体で、**どの60分を切り取っても 900回まで**（`library` と `check` それぞれ。設定 `CHECK_PER_HOUR` / `LIBRARY_PER_HOUR` で下げられます。カーリルの上限 1000回を こえる値には なりません）
- 1つの図書館には、**どの1分を切り取っても 20冊まで**（前の1分と合わせて数えます）
- 1つの接続元から、1分に **20回まで**
- カーリルが 403・429・503 を返したら、しばらく みんなで待ちます
- 数える係が ない・こわれた・おそいときは、**問い合わせを止めます**（あいまいなときは「だめ」にします）
- **1つの鍵は、1つのサイト（1つの数える係）だけで** 使ってください。いくつものサイトで同じ鍵を使うと、回数を合わせて数えられません

## 分かっている注意

- 「同じサイトから来た」という目印は、偽ることができます。最初の ふるいで、本当の守りは 数える係です
- 接続元ごとの制限は、たくさんの接続元から来ると すり抜けられます。そのぶん、サイト全体の回数で守ります
- ホスティングに **古い公開版** が残っていると、停止スイッチや数える係が効かないことがあります。古い版は消してください
- これは見本です。専門家による点検は受けていません
